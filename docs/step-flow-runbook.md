# 工程の図解ページ 手順書

作り方ガイドの「縫い方」の枠を押すと開く、①②③の丸ボタンで手順を絵で追えるページ
（`step-<key>-<slug>.html`）を、**最短の手間とトークンで**増やすための手順書です。

最初のポンチョ（5工程・21図）は約20万トークンかかりました。そのうち半分以上は、
仕組み作り・下調べ・見た目の往復でした。仕組みはもうあるので、次からは下の手順で
**1ガイドあたり3〜5万トークン**を目安にできます。

---

## 1. 図の約束（全ガイド共通・変えない）

途中で約束を変えると、描いた図を全部描き直すことになります（実際、縫い代の色分けを
あとから足して全21図を直しました）。**先に決めて、ここに書いてから描く**。

| 何を | どう描く | 部品 |
|---|---|---|
| 布の表 | 薄い青で塗る | `OMOTE` |
| 布の裏 | 白 | `URA` |
| 縫い代（布端〜縫う線） | 薄い赤の帯 | `saBand(x, y, w, h)` |
| 縫う線（糸が通る所）・これから縫う | 赤の破線 | `stitch(x1, y1, x2, y2)` |
| 縫い終わった線 | 赤の実線 | `stitch(..., true)` |
| 返し縫い | 縫う線の端に短い二重線 | `backtack(x, y)` |
| かがり縫い（ジグザグ・手かがり） | 青のギザギザ | `zigzag(x1, x2, y)` |
| まち針 | 灰色の軸＋青い頭 | `pin(x, y)` |
| 動き（重ねる・折る・返す） | 青い矢印 | `arrow(x1, y1, x2, y2, BLUE, 曲がり)` |
| バイアステープ | 山吹色 | `TAPE` |
| 凡例 | 図の下の行 | `key(l, ["omote","ura","sa","stitch","zig"])` |

- 縫い代は実寸だと細すぎて見えないので、**太めに誇張**して描く（肩は 11px）。
- 断面図は、布を太い線（`layer()`）で描き、縫い代の部分の後ろに `saBand` を敷く。
- `<svg>` の中で `id` と `marker` は使わない。1ページに図が並ぶと id が重複します（矢じりは `arrow()` が線で描く）。

## 2. 最短の手順（1ガイドぶん）

### 手順0：どのガイドをやるか決める（人）

アクセスの多いガイドから。GA4 は手元のパソコンの Claude Code で見られます
（`docs/ga-mcp-setup.md`）。**キーを3〜5個まとめて**決めておくと、依頼が1回で済みます。

### 手順1：文章だけ先に作る（Claude → 人が確認）

いちばん安く直せるのはここです。図を描く前に、手順の分け方と文章だけを出してもらい、
チャットで確認します。

- 対象：ガイドの「縫い方」の各枠（`ja-howto-data.js` の `sew[].items`）
- 1枠を **3〜5手順** に分ける。1手順＝「何を・どこに」を1つ
- 各手順：見出し（h）・説明（text）・必要なら ※注意（note）。日英とも
- 人は「分け方」と「言い回し」だけ見る。OKが出てから図に進む

### 手順2：図を描く（Claude）

- `scripts/step-flow-data.js` にガイドのキーを足し、手順1の文章と `svg` を書く
- **形は部品で**。身頃・袋・筒など、そのガイド専用の形は関数を1つだけ足して使い回す
  （例：ポンチョは `ponchoPiece()` と、重ねた2枚の `stacked()` だけで5図を描いた）
- 座標は viewBox `0 0 360 240` の中。文字は 10〜12、凡例は y=232
- 英語は文字が長いので、ラベルは短く（例："start at the edge" → "from edge"）

### 手順3：生成して機械で点検する（Claude）

```bash
node scripts/gen-step-flows.js          # ページ生成・ガイドにリンク・sitemap
python3 -m http.server 8099 &
node scripts/check-step-figs.js <key>   # 文字のはみ出し・重なり ＋ 一覧画像
node scripts/audit.js                   # サイト全体の点検（0件になること）
```

`check-step-figs.js` が見つけたものは、画像を見る前に直す。**画像を何度も撮って
目で探さない**（ポンチョではここで往復が増えました）。

### 手順4：一覧画像を1回だけ見る（Claude → 人）

`/tmp/step-figs-ja.png` に全部の図が1枚に並びます。Claude はこれを1回見て、
絵として分かりにくい所だけ直します。人にもこの1枚を送ります。

### 手順5：コミットしてプッシュ（Claude）

複数ガイドをまとめて依頼したなら、ガイドごとに1コミット。

```

```

## 4. トークンを使いすぎないためのルール（Claude 向け）

ポンチョでの反省から。

| しないこと | 代わりに |
|---|---|
| 生成済みの HTML（`howto-*.html`）を丸ごと読む | データ（`ja-howto-data.js` の該当キー）だけ `grep -A` で読む |
| `audit.js` などのスクリプトを全部読む | このファイルと `review-checklist.md` を信じて、実行結果だけ見る |
| 手順ごとにページのスクショを撮る | `check-step-figs.js` の一覧画像1枚 |
| 人の確認前に全工程の図を描く | 手順1で文章の確認をもらってから描く |
| 描いてから図の約束を決める | 1章の表に従う。変えるなら先にこの表を直す |
| 1ガイドずつ依頼を往復する | 3〜5ガイドを1回の依頼でまとめる |

## 5. 落とし穴

- **`gen-ja-howto.js` でガイドを作り直すと、枠の「図解で見る」が消える。** 必ず
  `gen-step-flows.js` をあとに流す（消えていれば `audit.js` が教えてくれます）。
- **リンクは枠の文章の完全一致で差し込む。** ガイドの文章を直したら、
  `step-flow-data.js` の `match` も同じに直す。`<strong>` などのタグも含めて一致させる。
- **英語ガイドは和文と構成が違うことがある**（ポンチョは作り方そのものが違っていた）。
  `match.en` が無ければ英語ガイドからはリンクしない。英語の図解ページ自体は必ず作る
  （和英の対がないと `audit.js` が止まる）。
- 裁断の節（`#cut`）の枠を図解にするときは `anchor: "cut"` を付ける（戻りリンク先）。
- `check-step-figs.js` は JS を切ってページを開く。step-flow.js が手順を隠すと、
  隠れた図は大きさ0になって測れないため。
